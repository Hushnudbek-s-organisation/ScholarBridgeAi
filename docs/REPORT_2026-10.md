## 1. What was implemented (incl. recommender integration points)

### Probability compliance (binding rule: no admission probability without a validated methodology)
- The four student-facing surfaces — `api/chancing`, `api/planning`,
  `api/ai/admissions-advisor`, and the ChancingPanel / AdmissionsAdvisor
  UIs — now expose **fit scores + requirement signals only**. The
  probability dimension is returned as
  `ADMISSION_PROBABILITY = { available: false, reason: "no-validated-methodology" }`
  and labelled **"unavailable"** in the UI with an explicit
  "not a probability / not a guarantee" disclaimer.
- `estimateAdmissionChance` remains a **pure internal engine** (its
  sub-scores still power the "Why?" signals); it is no longer surfaced as a
  percentage anywhere.
- `check-chancing` (64 assertions) includes **static policy checks** that
  read the route/engine source and fail if a numeric probability is ever
  re-exposed.

### Recommender (integrated, not a demo)
- **Engine** `src/lib/recommend.ts` — pure, deterministic. FOUR SEPARATE
  dimensions: (1) subject fit (exact > synonym > partial > weak > none;
  conservative synonym groups; unknown stays neutral 0.5), (2) eligibility
  (each published requirement → met / unmet / **unknown** — unknown is
  never unmet; GPA converted only when a scale is known or value ≤ 4;
  text requirements carried unscored), (3) affordability + funding
  (budget compared only when tuition is in USD — non-USD stays unknown,
  never cross-converted; conservative scholarship matching), (4)
  **admission probability — never computed**; every result carries
  `{ available: false }`. Ranking is a 0–100 **match score** (labelled as
  such) with plain-language `rankingFactors`. Provenance per program:
  verification status, source URL, last-verified date, stale flag
  (>180 days = "may be outdated"). Missing student inputs are listed in
  `missingInputs`, never counted against the student.
- **API** `POST /api/programs/recommend` — session required;
  `requireProfileAccess` (a client-supplied `profileId` is checked against
  the session → 403 for foreign ids); interests required (400 + guidance,
  never silently defaulted); strict clamps on every field; input
  resolution **request > profile > unknown** with the source of each value
  returned in the payload (`inputs.*.source`); DB failure → **503
  `data_unavailable`** — the catalog is never replaced with mock data.
- **UI** `src/components/RecommendationStudio.tsx` (tab `#recommend`,
  journey group in the sidebar, `isNew` badge):
  - inputs: interests (required, tags, ≤12), degree level, GPA + scale,
    tests, countries, budget, funding need, teaching language, start year —
    **every one skippable** with a why-optional explanation and a
    "Don't know yet" default; profile prefill is **flagged**
    ("Prefilled from your saved profile — edit or clear before running");
    cleared prefilled fields send explicit null (user-confirmed unknown),
    never-filled fields fall back to the profile server-side.
  - result cards show the four dimensions separately, provenance badges
    (verified / not verified / stale + last-verified date), next
    application cycle with deadline (unverified cycles flagged
    "not verified by an official source"; no cycle → "check the official
    program page"), ranking factors, missing inputs, considerations, and
    the probability dimension as **unavailable** with the policy text.
  - actions: **save** (`POST /api/saved-programs`), **compare** (client-side
    tray, ≤3, side-by-side table), **open university** (deep-link focus
    into the University Explorer via the existing
    `scholarbridge:focus-record` event), **create application plan**
    (`POST /api/applications` with deadline only when published), official
    page link (only when a URL exists in the catalog).
  - states: loading (spinner, `role=status`), error (401 / 400 / 503 /
    network — each with an honest, translated message), empty (no matches —
    no invented programs), success (results + count + scanned count).
  - i18n: full **`recommend` namespace, 111 keys × en/uz/ru**; input
    provenance panel shows where each value came from
    (you entered / from your profile / not provided).
- **Regression** `npm run test:recommend` — **74/0** on an isolated
  throwaway embedded Postgres (`:55450`, wiped each run): engine units
  (synonyms, multi-interest, GPA scales, missing-data neutrality,
  no-probability static checks, provenance/stale with fixed dates,
  affordability incl. non-USD→unknown, ranking order) + API
  (401 anon, 400 no-interests, 200 happy path, ranking, eligibility,
  affordability, cycle/isEstimated, provenance, probability=false, input
  source tags, 403 bob-claims-alice, save + plan ownership, 403s,
  no-requirements program) + i18n ×3 long-text parity (key parity ≥100,
  compliance strings non-empty in all locales, no numeric % in the
  probability text).
