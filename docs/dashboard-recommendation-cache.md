# Dashboard recommendation cache freshness

The dashboard response itself is never cached (`private, no-store`). Only the derived `recommended` sub-result uses `src/lib/dashboardRecommendationCache.ts`: a process-local async TTL cache, keyed by exact profile ID + locale + UTC date, with a 15-second TTL and 500-entry bound. Concurrent calls for the same key share the in-flight promise; a rejected promise is removed; invalidation during pending work does not let that old promise replace a newer result. The bound is insertion-order eviction, not LRU.

A successful profile PUT/DELETE (`/api/profiles/[id]`), portfolio activity POST/PATCH/DELETE (`/api/activities`), and saved university/scholarship POST/PATCH/DELETE invalidates all locale/date cache keys for the affected profile. Invalidation happens after the awaited database write and only on the success path. Validation/auth/DB failures do not invalidate a valid result. This is profile-scoped and does not clear the shared catalogue caches. The shared catalogue has its separate cache TTL/invalidation contract; admin catalogue writes do not force every student's recommendation result out of the per-profile cache.

Product freshness contract: a successful mutation is visible to the next dashboard request on the same server process. In a multi-instance/serverless deployment, another process can retain its already-computed profile recommendation result for at most the 15-second TTL. The endpoint's counters/deadlines and the rest of its response are live on every request. Global scholarship/opportunity reads inside the recommendation computation also inherit that 15-second profile-result freshness window.

`npm run test:dashboard-cache` exercises concurrent reuse, failures/retries, key/profile isolation, expiry, bounded size, clear, profile-scoped multi-locale invalidation, invalidation during a pending promise, and protection of a replacement entry from a late rejected promise. The database integration suite additionally exercises successful profile and saved-list mutations plus a rejected activity mutation against the actual route handlers.
