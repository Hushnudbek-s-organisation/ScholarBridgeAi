## Xatoni muvaffaqiyatga aylantirmaydigan recovery

`revisionFencedCache` ikki bounded snapshot urinishidan keyin ham revision o‘zgarsa eski muvaffaqiyatli natijani qaytarmaydi. Yangi read-failure taxonomy bu holatni `snapshot_changed` 409 sifatida ajratadi. Client faqat shu aniq GET holatini bir marta qayta o‘qiydi; boshqa 409/CAS, 401/403, 500/503, transport xatolari va mutation’lar avtomatik qayta bajarilmaydi. Sof regressionlar buni alohida tekshiradi. Bu mexanizm Build4’dagi noma’lum 500 sababi aynan revision race bo‘lgan degan da’vo emas.

Server diagnostikasi faqat tasodifiy request ID, qat’iy category/kind/dbCode va route-owned joy nomini chiqaradi. SQL, query parametrlari, profile ID, login qiymatlari, credential, URL yoki raw error message/stack chiqarilmaydi. Disposable E2E harness faqat shu structured allowlist satrlarini saqlaydi; production setting yoki provider o‘zgartirilmaydi.
